补齐概念的缺失：此前项目**没有「掌握」这个概念** —— `status='known'` 全代码库无一处

### 新增 — 掌握度模型（`app/services/mastery.py`）

**核心判断：必须是「识别」与「回忆」两个维度，不能合成一个概率。**

- **Pellicer-Sánchez (2015, *SSLA*)**：8 次语境遇见后，词形识别 **86%**、意义识别 **75%**，
  但回忆只有 **55%**；3–4 次遇见后阅读速度显著变快。同一批词、同样遇见次数，
  识别与回忆差 20–30 个百分点。
- **van den Broek et al. (2022, *Cognitive Science*)**：即使在语境中理解了，
  也不一定能回忆出词形或词义。
- **Webb (2007, *Applied Linguistics*)**：10 次以上收益更稳定，但**不存在保证学会的最小次数**
  —— 所以遇见次数是概率性证据，不是判定条件。

于是「没查过 + 见了几次」这个信号（用户指出、系统一直在采集却从未使用）被正确地
定位为**识别级证据**：

- 能**认出来** → 继续输入（下篇继续埋）
- 能**想起来** → 停止输入，去做提取练习

**参数是算出来的**：每次干净遇见 +0.42（识别层）由「8 次 → 75% 识别」反推；
+0.30（回忆层）由「8 次 → 55% 回忆」反推。查词 −0.9、答对 +1.1 / 答错 −1.3
分别对应「自陈不知道」与 testing effect。

**等级由证据类型决定，不由概率决定**：`recalled` 必须有答题证据，
纯遇见再多也不算（8 次遇见后回忆仅 55%）。

### 新增 — 选词接入闭环（`app/services/selection.py`）

原 `_select_new_words()` 只按 FSRS 到期 + 词频，不知道已掌握的词、目标考试、
重遇进度。现在分四层：

到期复习 → **重遇缺口**（见过但识别未建立，越接近 4 次越优先）→
目标考试词表里的新词（高频优先）→ 兜底。**明确排除 `recalled`**。

- 新增**目标考试**设置（`settings.target_exam`，默认四级），决定下一篇埋哪些词。
  实测三个考试选出的第 3 层词 100% 属各自词表且互不相同。
- 统计页新增目标考试选择器与掌握度分布。

### 修复 — 三处踩坑（都写进注释与文档了）

1. **先验把证据淹没**：默认假设给最高频两档 `rate=1.0`，logit 高达 9.2，
   一个用户明确查过的词被判「识别 100%」→ 先验封顶 ±2.0。
2. **等级不该看概率**：概率是群体估计，等级必须是个体证据 → 抽出 `level_of()`。
3. **18 万词不能逐个算**：`refresh()` 只处理有证据的词，全量刷新 **0.027 秒**。

### 性能 — 底层优化

- 新增**表达式索引** `COALESCE(NULLIF(frq,0), bnc)` —— 查的是表达式，建在 `frq` 上的
  普通索引完全用不上（`EXPLAIN QUERY PLAN` 已确认命中）。

## [2.4.1] - 2026-09-16（词汇差距统计；**未发布到 PyPI**）

把前一轮铺好的地基（考试词表 + 定级测试）连成统计页上的数字。

### 新增 — 覆盖率与考试缺口（`app/services/vocab_gap.py`）

**覆盖率按词频档位给语料加权，不是「认识多少个词表里的词」。**
实测：CET4 大纲词表（3,846 词）只覆盖四级真题语料 **15.8%** 的 token ——
因为词表装的是内容词/考点词，剩下 84% 全是基础词与功能词（the / of / is …）。
拿「词表掌握百分比」当「能读懂多少」会严重失真。

正确做法：把语料每个 token 映射到它所在词频档位的掌握率再求和，
这样「认识多少」直接换算成「读懂多少」，也就是 i+1 判据本身。

缺口不设「掌握率 < 0.5 就算不认识」的硬阈值，而是取期望值
`Σ(1 − 掌握率)`，让「掌握了 70%」的词表给出连续而非被阈值一刀切的缺口。

未做定级测试时自动铺一条**默认假设**（掌握最高频 2,500 词，`source='default'`），
并在界面上**明确标注「这不是测出来的」**，真实测试完成后自动取代。

### 修复 — 词典缺失 11.9% 的高频词

实测 ECDICT 中 COCA 前 20,000 的词里有 **2,119 个（11.9%）不在库内** ——
包括 `i`、`n't`、`others`、`including`、`recent`、`internet`、`percent` 这种。
覆盖率会把「无法还原的 token」算作不认识，于是**覆盖率被系统性低估**。

- `tools/import_exam_tags.py` 新增 `--add-missing`：补入高词频且带释义的缺失词。
  已补 5,784 个，库内 175,776 → **186,060** 词。
- **根因是只看 `frq`**：ECDICT 里有一批常见词的 COCA 排名为 0 但 BNC 有排名
  （`percent` 就是 frq=0 / bnc=2802），共 2,967 个。
  三处（补词筛选、覆盖率分档、定级题库）统一改为**有效词频 = `COALESCE(NULLIF(frq,0), bnc)`**。
- 效果：四级语料无法还原的 token 从 **11.0% 降到 8.1%**（剩下的基本是专名与连字符复合词）。

### 性能

覆盖率首次计算需要把 30 万 token 做词形还原再按档位聚合。
初版对每个词元单独查一次库（一万多次 SELECT），实测 **151 秒**；
改为分批 IN 查询后 **0.8 秒**（188 倍），结果按级别缓存。

|---|---|---|
| 真题覆盖率 | **78.9%** | 77.6% |
| 每 300 词生词 | 63 个 | 67 个 |
| i+1 区间（95–98%） | 未达标 | 未达标 |

各考试缺口：四级还差 2,502 / 六级 4,174 / 考研 3,482 / 雅思 3,580 / 托福 6,026。

## [2.4.0] - 2026-09-16（词汇差距闭环：考试词表 + 定级测试 + 重遇机制 + 蒸馏修正；**未发布到 PyPI**）

本轮把「提升词汇量」从一句口号变成可计算、可验证、能驱动阅读的闭环。出发点是
**罗肖尼《如何永远学会一个单词？》**（[BV1ns4y1A7fj](https://www.bilibili.com/video/BV1ns4y1A7fj/)，
253 万播放，理论根基是 Krashen 的可理解输入假说）给出的两条操作规则：

> ① 找 95–98% 词汇覆盖率的可理解文本（300 词里 6–15 个生词），大胆略过生词
> ② 在「变化的语境」中重遇同一个生词 ≥ 12 次

对照下来发现项目**只做了一半**：①方向对但从不测量，②完全没实现。

### 新增 — 词汇量定级测试（`app/services/placement.py`）

Yes/No 词汇量测试（Meara & Buxton），20 档等宽抽样 + 伪词虚报校正，194 题约 3–5 分钟。

- **40 个伪词逐个校验过不在 ECDICT 77 万词条中**，并有单元测试守着 —— 伪词一旦是真词，
  虚报率被高估，词汇量会被系统性低估。
- 题面**只下发单词本身**，不下发词频档位与伪词标记，否则翻一眼网络面板就能作弊。
- 用 **PAVA 保序回归**约束掌握率单调不增 —— 这是修正估计偏差的关键。
- 实测精度：模拟「真实 4,000 词 + 6% 虚报」得到 4,054（误差 1.4%）；
  在虚报倾向 2%–20% 区间内估计值稳定在真实值 ±200。
- 前端：分页勾选（每页 16 个，13 页），比逐词作答少 300+ 次点击。

**调优记录（连续踩坑，都已写进注释）**：
- 最初用不等宽档位（末档 6,000 词）× 15 题 → 末档一次 `5/15` 的抽样噪声被档宽放大成
  **2,000 个凭空的词**，估计值系统性高出 2,758 → 改等宽 1,000 × 8 题 + PAVA，MAE 降到 891。
- 伪词只有 16 个时虚报率噪声极大（一次 `5/24` 的波动被当成 20.8% 从每档扣掉，整体低估 30%）
  → 扩到 34 个 + 收缩先验，MAE 630。

### 新增 — 重遇机制（`app/services/encounter.py` + `app/services/lexicon.py`）

补上视频方法里被完全漏掉的第二根支柱。

- **口径**：`重遇次数(w) = COUNT(DISTINCT article_id)` —— 数的是「跨了多少篇文章」，
  而不是「看了几眼」。同一篇文章看 12 遍不算重遇，这正是「语境要变化」的度量。
- **关键修复**：`words.encounter_count` 此前只在**用户查词**时 +1 —— 看到了但没查就完全
  不算遇见，而方法的要害恰恰是「反复遇见」。现在**文章生成即记录**（幂等，靠
  `(word_id, article_id) WHERE action='seen'` 的部分唯一索引）。
- 除目标生词外，还记录**正文里出现的已有学习词** —— 后者才是真正的「在新语境中重遇」。
- `app/services/lexicon.py` 是共用底座：库里存词元、语料跑屈折形式，
  实测只有 **53.2%** 的词型能直接查到，词形还原后升到 **94.9%**。
- 统计页新增「重遇进度」，按跨篇数排序。

### 修复 — 生成 prompt 的两套风格源打架

1. **硬编码基准是 205 篇旧数据，实测偏差明显**：复合句 50% → 实测 **65%**；
   状语从句 30% → 实测 **17%**；平均句长 20 → 19.2。已换成 **273 篇四级真题**的实测值。
2. **生效画像来自《傲慢与偏见》，且排在基准之前**、写着 `Follow this profile while still
   meeting the requirements below` —— 等于让一本 19 世纪小说压过四级真题。两者实测差距是
   实质性的：短句占比 10% vs 29%、平均词长 4.85 vs 4.41、TTR 0.089 vs 0.055。
   现在真题基准是骨架且排在前面，个人画像降级为末尾的 `OPTIONAL REGISTER NOTE`，
   并显式声明「基准在句长/复杂度/覆盖率上优先」。
3. **最要命的一条**：画像往 prompt 里注入「低频词占比约 100%」，而本产品的第一性原理是
   i+1（95–98% 覆盖率 = 绝大多数词你认识）—— 这条提示在指示模型往生僻词方向写，方向正好相反。
   `profile_prompt_hint()` 现在**刻意不输出** `low_freq_ratio`。
4. **`Article` 漏传 `target_words`**：它默认 `"[]"`，导致 API 一直返回空的目标词列表，
   重遇机制也拿不到「文章里刻意埋了哪些词」。已修并有回归测试。

## [2.3.2] - 2026-09-16（知识图谱重建 + 全量蒸馏；**已提交，未发布到 PyPI**）

### 修复 — 知识图谱「比例和动画」

修前实测（浏览器 + canvas 内省，非目测）：图永不静止，0.5s 内平均位移 356px、
节点速度峰值 **9651 px/帧**；150 个短语节点 **连接度全部为 0**，被斥力推到画布
上下边缘排成两条硬边；画布只有 608px 宽（视口 1440px）。

- **多 rAF 循环叠加**：物理循环标志 `_looping` 挂在 `graphState` 上，而 `drawGraph()`
  每次都重建 `graphState` → 标志永远是 undefined，每切换一次筛选/重建一次就永久多出
  一个 `requestAnimationFrame` 循环，物理步进被叠加 N 倍（实测切换 4 次后 30fps → **238fps**）。
  改为模块级循环句柄，重建前先 `cancelAnimationFrame`。
- **物理永不收敛（极限环）**：斥力 `900/d²` 无上限、无 dt 归一化、无速度上限，阻尼压不住；
  边界用硬裁剪把节点压死在画布边上。而且只靠阻尼在数学上就收不了 —— 合力通常**没有平衡点**，
  系统会停在永久极限环上（实测速度长期稳定在 0.1~0.3px/帧，永远不归零）。
  → 重写为：软化斥力 + 单对力上限 + 速度上限 + 柔性边界回推 + **alpha 退火冷却**（力整体
  衰减到 0，保证必然静止；d3-force 同款）+ **子步进**（无头/后台 rAF 掉到 30fps 时 dt=2，
  一步走两帧会过冲）。收敛后彻底停掉循环，不再空转。
- **画布比例**：`wide-view` 只覆盖 `stats/articles/vocab`，知识库三页（书架/材料/图谱）漏了，
  图谱被塞进 720px 阅读栏 → 补上；并且把宽窄布局的切换**提前到渲染之前**（原来先渲染再变宽，
  canvas 按旧窄宽度定尺寸，之后再被拉宽，比例永久错）。
- **语义着色与辨识度**：`--accent` 在深色主题下就等于 `--text`，短语和词同色分不出来 → 短语
  改用独立色相；标签/连线颜色改为读主题变量（原来写死 `rgba(253,252,252,0.55)`，浅色主题下
  白字白底看不见）。节点半径按类型分层 + 标签简易占位检测（原来标签糊成一团）。
- **各向异性映射**：布局的自然形状是圆的，画布是 1020×598 横长条，直接跑物理会被高度卡住、
  左右永远空一片（实测 spanY≈1.00、spanX≈0.50）。改为物理在 min(W,H) 的正方形域里跑，
  渲染/命中测试时按画布长宽比拉伸。

### 修复 — 图谱内容质量（真凶是数据，不只是渲染）

- **150 个短语节点 100% 孤立**：`rebuild()` 只建节点不建边，短语没有任何弹簧牵引，纯靠斥力
  被推到边界。改为**不产生孤立节点**：只有真的被文档连上的词/短语才建节点，并新增
  文档→短语的 `contains` 边。重建后 73 节点 / 174 边 / **孤立节点 0**。
- **`rebuild()` 语义改为全量重算**：原实现靠 `ON CONFLICT ... weight = weight + excluded.weight`
  累加边权，反复点「重建图谱」会让权重无限膨胀，且陈旧节点永远清不掉 —— 「重建」本就该是重建。
- **词节点混入整句碎片**：批量识词/查词兜底曾把句子写进 `words`（`rget What They Learn?`、
  `urnal, s`、`Old Chen`、`te`），32 个词节点里 13 个是碎片。词节点现在只接受单个小写英文词，
  并按词形去重（`every` / `Every` 这类重复项只留投入度更高的那条）。
- **`phrases` 表 198 条 `quot` 垃圾**：早期从 HTML 抓取残留 `&quot;` 实体，产出
  `quot says`(频率 87，榜首) / `said quot` / `quotes quot` 等。**它不只污染图谱 —— 文章生成
