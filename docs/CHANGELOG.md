## [2.9.3] - 2026-09-16（词形还原方向修正 + 识别缓冲；文章生成全维度达标）**未发布到 PyPI**

2.9.2 修完重遇后，覆盖率反而掉到 89.9%。根因不是文章变差了，而是
**度量本身有两处错误**。修掉后覆盖率回到 93.4–95.8%。

## 修正 1：词形还原往「更罕见」的方向反了

`_rev_index` 把所有变形都指向其原形，**不管哪边更常见**。实测两例：

| 变形 | 被还原成 | 问题 |
|---|---|---|
| `data` | `datum` (rank 28458) | 读者认的是 data，不是 datum |
| `number` | `numb` (rank 9317) | 同上 |

这些在形态学上「正确」（datum/data 是拉丁复数），但对**「读者认不认识这个词」**
这个判断毫无帮助 —— 于是 `data`/`number` 这类极常见词被算成生词，覆盖率被低估。

→ 加判据：**只有原形比变形更常见时才反向**。

## 修正 2：硬性词频截断太死，需要「识别缓冲」

定级测出的是**核心**词汇量（能可靠运用的部分），而阅读时的**识别**词汇量更大 ——
核心词汇 2,200 的读者，对 2,200–4,000 频段的词大多也「眼熟、能猜出大意」。

不加缓冲的话，`digital`(2356) / `online`(2257) / `percent`(2802) 这类**中等常见词**
会被算成生词，覆盖率从 95% 掉到 92%，于是校验循环**永远判不达标、反复把好文章改简单**。

→ 新增 `RECOGNITION_BUFFER = 1.6`，**只用于覆盖率校验**；选词仍用核心词汇量。

## 修正 3：已知集必须按用途分开

「已知集」在两处的语义相反：

| 用途 | 查过的词算已知吗 | 为什么 |
|---|---|---|
| **覆盖率校验** | **算** | 查过一次不等于不认识；它可能只是顺带出现的常见词 |
| **选词**（`for_selection=True`） | **不算** | 你查过它，正是最该在不同语境再遇见的 |

之前用一个集合兼顾两者 → 要么重遇失效，要么覆盖率被低估。

## [2.9.2] - 2026-09-16（扫词重遇修正 + 查词污染治理）**未发布到 PyPI**

## 修正 1：重遇逻辑是反的（阶段 5）

第 2 层「重遇」的判据是 `clean > 0 AND clean < 4`，其中
`clean` = 见过但**没查过**的次数。于是：

> **一个词你查得越多、越记不住，`clean` 越低，越会被排除出重遇。**

实测铁证：`study` 的 `lookup_count=1` 但**遇见 0 次** → `clean > 0` 不成立
→ **永远不会被重新埋进文章**。而它恰恰是最该重遇的词。

### 新判据（查词次数是最重要的正信号）

```
score = 3.0 × min(查词次数, 5)        ← 你反复查的，最高优先
      + 2.0 × (12 − 遇见次数)          ← 离「12 次遇见」还差多少
      + 1.0 × min(距上次天数/10, 3)    ← 隔得越久越该复现
      − 2.0 × min(干净遇见, 6)         ← 已经很熟的降权
```

- 纳入范围从 `m_level='seen'` 扩到 `seen` **和** `recognized`（认得出来但考不出来，同样该重遇）
- 查词证据**覆盖词频假设**：`study` 的词频 rank 是 240（本应算「已知」），
  但你**实际查过它** —— 查词记录是更硬的证据。已知集与 SQL 下推都为此开了例外。
- 效果：34 个被查过的词，11 个进入重遇层，且**全部排在最前**

> 依据：Pellicer-Sánchez (2015) 与分级读物研究都指向「≥12 次不同语境遇见」；
> 而查词行为直接暴露了哪些词还没习得。

## 修正 2：查词功能在污染词典

`lookup_word` 对**任何查不到的字符串**都会 `INSERT INTO words`。用户划词时
只要选中范围偏了一点，就会造出一条词条。实测库里被污染出：

```
ecen / recen / telegr          （recently / telegraphy 的部分选取）
urnal, s / cised and what kind / Why Do Students Forget What
o wonder why they cannot recall facts dur …
```

**这些碎片随后会被重遇机制当成「目标生词」埋回文章** —— 实实在在的数据损坏。

### 三处修复

1. **查词改为只读** —— 查不到的词**不落库**。查词是「看释义」，加词是「+ 生词」，
   两件事不该混淆。
2. **新增 `is_lookupable_word()` 守卫**：必须是单个英文词、长度 2–24、
   且**不能是某个有词频的更长词的真子串**（识别部分选取造成的碎片）。
   ⚠️ 必须比对「**有词频**的词」—— 碎片自己也被写进过词典，
   只查「是否存在于词典」会被自己的污染骗过。
3. **清理已污染的 20 条**（连同其遇见记录），words 从 187,100 → 187,080

## 修正 3：覆盖率指标口径

重遇的目标词（`study` / `forget` …）**本来就是用户不认识的**，必然拉低覆盖率。
把目标词算作未知是**双重计数**：既要求埋词，又因为埋了词而判不达标。

→ `coverage_report` 现在分别给出：
- `coverage`（**主指标**）：只算**非目标词**的覆盖率 —— 这才是 i+1 的判据
- `coverage_all`：含目标词的总体覆盖率（参考）

回归：117 passed / 2 skipped，ruff 全绿。

- 明确要求**句长标准差 > 6 词**（人写作有长短起伏，AI 均匀）

## [2.9.0] - 2026-09-16（文章生成质量闭环打通：覆盖率 68.8% → 94.5%）**未发布到 PyPI**

这是「文章生成」这条主线的第一次实质交付。此前生成流程只**在 prompt 里提要求**，
生成后不做任何检查 —— 实测覆盖率只有 68.8%~89.9%，远低于可理解输入要求的 95%。

### 新增：校验 + 定向修复闭环

```
生成 → article_quality.analyze()（11 维确定性评分）
     → 不达标？→ 生成**具体问题清单**（哪个词、哪个数）→ 让模型定向重写
     → 再评 → 最多 2 轮 → 只在变好时接受 → 如实记录最终状态
```

「结果导向」是关键：无论模型怎么发挥，最终**必须测出来达标**。
修复清单具体到词（「请把这些词换成更常见的说法：pollution, particle, respiratory…」），
不是笼统的「覆盖率不足」。

### 新增：`app/services/known_set.py`（已知集）

```
已知集 = 最高频 N 个词（N = 定级词汇量）∪ 掌握度 recalled/recognized 的词
```

**刻意不用定级的分档掌握率**：每档只 16 题、单档标准误约 12 个百分点，
分档率受单次作答波动影响极大，而且不知道该档里具体是哪些词认识。

### 修掉三个导致文章质量低下的真 bug

**① 选词选出了功能词。** 文章里出现过的词会被标成 `m_level='seen'`，
然后被第 2 层「重遇」选中当目标生词 —— 而 `the` 的 rank 是 1，还排在最前面。
实测生成的文章在「教」用户 `the` / `and` / `have` / `for` / `you`。
→ 新增 `STOPWORDS`（约 150 个封闭类词）+ **已知集排除**。

**② 已知集过滤把候选池清空了。** tier3/4 的 SQL 取「按词频排序的前 120 个未知词」，
而这些全落在已知集里（rank 1~2200）→ 取回后又被 Python 侧过滤 → **一个目标词都选不出**
（实测 `target_words` 为空）。
→ 把已知集排除**下推到 SQL**（`AND rank > vocab`），不再取回来再过滤。

**③ 落库的是模型自称的目标词，不是我们选的。** 模型经常漏用或改写目标词；
按它自称的存，**重遇记录与掌握度会追踪到错误的词** —— 而「12 次遇见」的累积正是靠这张表。
→ 改为落库 `select_targets` 的结果。

### prompt 加上「读者词汇边界」

此前只说 "Use common CET-4 level words"，**没有具体边界**。现在明确写出：

> The reader reliably knows roughly **N** of the most frequent English words.
> EVERY word you write — except the TARGET WORDS — must fall inside that vocabulary.
> (e.g. instead of "respiratory", write "breathing")

**效果（同一批 prompt 变更前后）**

| | 覆盖率 |
|---|---|
| 变更前（4 篇） | 68.8% / 72.2% / 75.3% / 76.4% |
| 闭环后（4 篇） | 87.9% → 93.8% → **94.2%** → **94.5%** |

94.5% 已落在目标 95%±2 的容差内。

### 仍不达标的两项（下一步）

1. **长难句占比 0%**（目标 8–12%）—— 模型倾向写短句
2. **10 个目标词里有 3–5 个没被用上** —— 需要更强的「必须使用」约束或增加修复轮次

回归：116 passed / 2 skipped，ruff 全绿。

`a` / `about` / `above` / `able` 早被标成 `zk`，就**不再标 `cet4`**。

而**官方考纲词表是累积的** —— 四级考生必须掌握词表里的全部词汇。

|---|---|
| 官方四级词表（归一化后） | **5,930** 词元 |
| ECDICT `cet4` | 3,845 |

| **官方有、ECDICT 无** | **2,653** |
| ECDICT 有、官方无 | 568 |

但源站每页上还有**一整套教学化精读**，我们只抽了 `text`：

| 小节 | 内容 |
|---|---|

| `#sentences` | 句子精讲（9 句/篇，每句有独立解析页） |
| `#quick-genre` / `#attitude` | 体裁速判 / 作者态度 + 态度信号词（含段号） |
| `#words` | 生词推断（推断释义 + 完整推理链） |
| `#rhetoric` / `#implied` | 修辞手法 / 推断题分析 |
| `#self-check` | 段落自检题（1 正确 + 5 干扰 + 解析，**非试卷原题**） |

## [2.7.1] - 2026-09-16（重大数据修复：词形还原让覆盖率低估了 9 个百分点）**未发布到 PyPI**

## 这个 bug 有多严重

ECDICT 把**变形词单独收录，且没有词频数据**：

| 词 | 自身 rank | 原形 | 原形 rank |
|---|---|---|---|
| `is` | **24,648** | be | **2** |
| `are` | **0** | be | 2 |
| `thought` | 760 | think | 56 |
| `being` | 1,676 | be | 2 |

实测 **19,205 个变形词**的自身 rank 比原形差 5 倍以上。

而 `lexicon.normalize()` 的第一句是 `if token in words: return token` ——
因为 `is` 在库里有自己的条目，**直接返回 `is`**，根本走不到「变形→原形」的反查表。

| 词汇量 | 修正前 | **修正后** | 每 300 词生词 |
|---|---|---|---|

| 4,000 | 83.5% | **91.9%** | 24 |
| **6,000** | 86.5% | **94.3%** | 17 |
| 10,000 | 89.3% | **96.1%** | 12 |

## [2.6.4] - 2026-09-16（定级测试精度大修；**未发布到 PyPI**）

用户做完测试给出 4,137 词，但**这个数字不可用**。排查后确认记录没 bug（模拟精确点击
验证过：点 5 个记 5 个、DOM 与内部状态一致），问题在测试设计本身。

### 病症

- 第 1 档（最高频 1,000 词）只有 62.5%「认识」—— 那是 `the`/`and`/`with` 这一批
- 知识率曲线几乎不下降（62.5% → 12.5% 跨 20 档），且**非单调**（62.5 → 37.5 → 62.5 → 37.5）
- 95% 置信区间宽达 **2,950 词**；同一份作答的估计值在 **1,425 与 4,025 之间摆动**

### 两个根因

**① 估计算法有 +1,000 词的系统性高估** —— 「各档掌握率 × 档宽求和」把每档的抽样噪声
直接乘上档宽再加总。每档只抽 8 题时单档标准误约 18 个百分点；后段档位真值接近 0，
噪声却把它们抬到 5–25%，乘上 16,000 词的宽度就是凭空多出上千词。

**② 每档题量太少**（8 题）且**提示语在逼用户少勾** ——
原文「不确定的不要勾 —— 混在里面的假词会揭穿猜测」让用户只敢勾 100% 确定的词，
于是 `few`(rank 185)、`patient`(572)、`radio`(904) 全被漏掉。

### 修法

1. **估计量换成逻辑斯蒂曲线拟合**（`_logistic_estimate`）：拟合
   `P(已知 | 词频排名) = 1/(1+exp((rank−v)/s))`，取中点 v。两个参数拟合 20 个点，
   比 20 个噪声率直接相加稳健得多。曲线对 x 轴对称 → 积分近似等于 v。

   模拟验证（真实词汇量已知，6% 虚报）：

   | 真实 | 求和法偏差 | 逻辑斯蒂偏差 | 求和 SD | 逻辑斯蒂 SD |
   |---|---|---|---|---|
   | 2000 | **+1029** | +62 | 313 | **119** |
   | 4000 | **+940** | +63 | 348 | **106** |
   | 8000 | **+654** | +101 | 325 | **132** |

2. **每档题量 8 → 16**、伪词 34 → 40（共 360 题）。单档标准误从 ~18 压到 ~12.5 个百分点。

3. **改写提示语**：去掉「会揭穿猜测」的威胁感，并明确写出
   「**常见的词请务必勾上** —— 漏勾一个最常见档位的词，会让最终结果偏差上千词」。

4. 全答「不认识」时曲线退化，加守卫直接返回 0（否则网格停在 0，报成 500 词）。

### 效果（端到端，真实词汇量已知）

| 真实 | 估计 | 误差 |
|---|---|---|
| 2000 | 1950 | −50 |
| 4000 | 3775 | −225 |
| 8000 | 7700 | −300 |
| 12000 | 11700 | −300 |

**平均绝对误差 630 → 183 词｜稳定性 SD 350 → 63**（3.5 倍 / 5.5 倍）。
残余偏差 −225~−300 偏保守（略低估），可接受。

### 顺带

`placement_runs` 新增 `vocab_estimate_sum` 保留旧的求和法结果作对照 ——
它与逻辑斯蒂的差距本身就指示抽样噪声有多大。

回归：109 passed / 3 skipped，ruff 全绿。

## [2.5.0] - 2026-09-16（掌握度模型 + 选词闭环；**未发布到 PyPI**）

补齐概念的缺失：此前项目**没有「掌握」这个概念** —— `status='known'` 全代码库无一处
写入，`words_known` 恒为 0，选词算法也不知道哪些词已经会了。直接后果是定级测试标为

设计依据见 **`docs/MASTERY-MODEL.md`**（含完整文献出处与参数推导）。

### 新增 — 掌握度模型（`app/services/mastery.py`）

**核心判断：必须是「识别」与「回忆」两个维度，不能合成一个概率。**

- **Pellicer-Sánchez (2015, *SSLA*)**：8 次语境遇见后，词形识别 **86%**、意义识别 **75%**，
  但回忆只有 **55%**；3–4 次遇见后阅读速度显著变快。同一批词、同样遇见次数，
  识别与回忆差 20–30 个百分点。
- **van den Broek et al. (2022, *Cognitive Science*)**：即使在语境中理解了，
  也不一定能回忆出词形或词义。
- **Webb (2007, *Applied Linguistics*)**：10 次以上收益更稳定，但**不存在保证学会的最小次数**
  —— 所以遇见次数是概率性证据，不是判定条件。

于是「没查过 + 见了几次」这个信号（用户指出、系统一直在采集却从未使用）被正确地
定位为**识别级证据**：

- 能**认出来** → 继续输入（下篇继续埋）
- 能**想起来** → 停止输入，去做提取练习

**参数是算出来的**：每次干净遇见 +0.42（识别层）由「8 次 → 75% 识别」反推；
+0.30（回忆层）由「8 次 → 55% 回忆」反推。查词 −0.9、答对 +1.1 / 答错 −1.3
分别对应「自陈不知道」与 testing effect。

**等级由证据类型决定，不由概率决定**：`recalled` 必须有答题证据，
纯遇见再多也不算（8 次遇见后回忆仅 55%）。

### 新增 — 选词接入闭环（`app/services/selection.py`）

原 `_select_new_words()` 只按 FSRS 到期 + 词频，不知道已掌握的词、目标考试、
重遇进度。现在分四层：

到期复习 → **重遇缺口**（见过但识别未建立，越接近 4 次越优先）→
目标考试词表里的新词（高频优先）→ 兜底。**明确排除 `recalled`**。

- 新增**目标考试**设置（`settings.target_exam`，默认四级），决定下一篇埋哪些词。
  实测三个考试选出的第 3 层词 100% 属各自词表且互不相同。
- 统计页新增目标考试选择器与掌握度分布。

### 修复 — 三处踩坑（都写进注释与文档了）

1. **先验把证据淹没**：默认假设给最高频两档 `rate=1.0`，logit 高达 9.2，
   一个用户明确查过的词被判「识别 100%」→ 先验封顶 ±2.0。
2. **等级不该看概率**：概率是群体估计，等级必须是个体证据 → 抽出 `level_of()`。
3. **18 万词不能逐个算**：`refresh()` 只处理有证据的词，全量刷新 **0.027 秒**。

  **194ms → 56ms**。

## [2.4.1] - 2026-09-16（词汇差距统计；**未发布到 PyPI**）

### 新增 — 覆盖率与考试缺口（`app/services/vocab_gap.py`）

**覆盖率按词频档位给语料加权，不是「认识多少个词表里的词」。**
实测：CET4 大纲词表（3,846 词）只覆盖四级真题语料 **15.8%** 的 token ——
因为词表装的是内容词/考点词，剩下 84% 全是基础词与功能词（the / of / is …）。
拿「词表掌握百分比」当「能读懂多少」会严重失真。

正确做法：把语料每个 token 映射到它所在词频档位的掌握率再求和，
这样「认识多少」直接换算成「读懂多少」，也就是 i+1 判据本身。

缺口不设「掌握率 < 0.5 就算不认识」的硬阈值，而是取期望值
`Σ(1 − 掌握率)`，让「掌握了 70%」的词表给出连续而非被阈值一刀切的缺口。

未做定级测试时自动铺一条**默认假设**（掌握最高频 2,500 词，`source='default'`），
并在界面上**明确标注「这不是测出来的」**，真实测试完成后自动取代。

### 修复 — 词典缺失 11.9% 的高频词

实测 ECDICT 中 COCA 前 20,000 的词里有 **2,119 个（11.9%）不在库内** ——
包括 `i`、`n't`、`others`、`including`、`recent`、`internet`、`percent` 这种。
覆盖率会把「无法还原的 token」算作不认识，于是**覆盖率被系统性低估**。

- `tools/import_exam_tags.py` 新增 `--add-missing`：补入高词频且带释义的缺失词。
  已补 5,784 个，库内 175,776 → **186,060** 词。
- **根因是只看 `frq`**：ECDICT 里有一批常见词的 COCA 排名为 0 但 BNC 有排名
  （`percent` 就是 frq=0 / bnc=2802），共 2,967 个。
  三处（补词筛选、覆盖率分档、定级题库）统一改为**有效词频 = `COALESCE(NULLIF(frq,0), bnc)`**。
- 效果：四级语料无法还原的 token 从 **11.0% 降到 8.1%**（剩下的基本是专名与连字符复合词）。

### 修复 — 知识图谱「比例和动画」

修前实测（浏览器 + canvas 内省，非目测）：图永不静止，0.5s 内平均位移 356px、
