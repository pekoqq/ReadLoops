## 一、生词数：由公式推导，不拍脑袋

### 文献依据

| 来源 | 关键结论 |
|---|---|
| [Nation (2006)](https://www.lextutor.ca/cover/papers/nation_2006.pdf) | 98% 覆盖需 8,000–9,000 词族；**90% 覆盖率下只有少数人获得充分理解**；98% = 每 50 词 1 个生词 |
| [Brown, Waring & Donkaewbua (2008)](https://eric.ed.gov/?id=EJ815119) | 分级读物实验：**每本约 5,500 词，设 28 个目标生词**；出现次数分 10–13 / 7–9 / 2–3 次三组 |
| [What can readers read after graded readers?](https://scholarspace.manoa.hawaii.edu/bitstreams/c6d886be-2937-46d3-8296-dd6d26e65729/download) | **习得一个词族需在文中遇见 ≥12 次** |
| [EDM2022](https://educationaldatamining.org/EDM2022/proceedings/2022.EDM-posters.99/) | 认识 >95% 的词才能靠阅读习得生词 |

### 推导

Brown 等的实验数据可直接反推**每个生词的平均复现次数**：

```
5,500 词 × (1 − 95%) = 275 个未知 token
275 ÷ 28 个目标生词 = 9.8 次/词
```

**公式**：

```python
N = floor( L × (1 − C) / R )
```

- `L` = 文章长度（320 词）
- `C` = 目标覆盖率（0.95）
- `R` = 每个目标词的文内目标复现次数

代入：

| R（复现次数） | N（目标生词数） | 依据 |
|---|---|---|
| 3 | **5** | 首次印象的最低复现 |
| 5 | **3** | 中等印象 |
| 10 | 1 | Brown 等的实验值，但 320 词的文章做不到 |

**还要扣除「偶然越界」**：专有名词、低频词会不可避免地混进来。
实测四级真题里专有名词占 4.2%，这部分不计入学习目标但会消耗覆盖率预算。

```python
INCIDENTAL_RATE = 0.025        # 初值，由实际生成结果校准
N = floor( (L × (1−C) − L × INCIDENTAL_RATE) / R )
  = floor( (320 × 0.05 − 320 × 0.025) / 3 )
  = floor( 8 / 3 )
  = 2
```

**结论：一篇 320 词的文章，目标生词 3–5 个（R=3 时取 5，R=5 时取 3）。**

⚠️ **但 320 词的文章根本放不下「12 次遇见」** —— 这是产品设计的根本约束。
所以「12 次」必须**跨文章累积**，这由现有的 `word_encounters` 承担。
一篇文章只负责「第一次或第二次印象」，系统负责把它推到 12 次。

**⚠️ 最终 N 不写死**：`R` 与 `INCIDENTAL_RATE` 都是**待校准参数**，
跑够 20 篇后用实测覆盖率回填，这是自动的，不需要人决定。

## 二、题材：从真题语料聚类得出，不瞎编

对 273 篇四级真题做 TF-IDF + K-means 聚类（K=8，纯代码可复现）：

| 题材簇 | 真实占比 | 聚类关键词 |
|---|---|---|
| **教育 / 学习** | **30.0%** | students, school, skills, education, teachers, music |
| **食品 / 农业 / 营养** | **16.1%** | food, genetic, eating, obesity, protein, meat |
| **居住 / 社区 / 就业** | **10.3%** | home, residents, internet, employees, city |
| **生活日常 / 儿童** | **9.9%** | water, sleep, kids, children, summer, play |
| **环境 / 气候** | **9.9%** | pollution, climate, warming, ocean, global |
| **认知 / 心理 / 决策** | **9.2%** | decisions, trust, pain, mind, success |
| **交通 / 科技伦理** | **7.7%** | driving, cars, robots, moral, traffic |
| **社交 / 健康** | **7.0%** | loneliness, social media, heart, health |

**算法**：
1. 选题材簇时**按上表占比加权随机**（教育 30%、食品 16%…）—— 分布忠实于真题
2. 簇内再选**具体角度**（从该簇的关键词组合生成切入，而不是"科技对生活的影响"这种空泛说法）
3. **轮转**：近 8 篇内不重复同一簇，避免连续读教育类
4. 复现脚本：`tools/analyze_exam_topics.py`（把上面的聚类固化成可重跑的工具）

## 三、语法：用依存句法分析，不用正则

**现状**：prompt 里只有 2 行手写要求，无校验。
**问题**：我上一轮用正则统计「定语从句占比 73%」，把 `that` 当关系代词导致严重虚高 —— **正则做不了这件事**。

**算法**：用 **spaCy 依存句法分析**（`en_core_web_sm`，约 12MB）。

| 语法点 | spaCy 判据 |
|---|---|
| 定语从句 | `relcl` 依存关系 |
| 状语从句 | `advcl` |
| 名词性从句 | `ccomp` / `xcomp` / `csubj` + `mark` ∈ {that, what, whether, if} |
| 非谓语动词 | `acl` / `advcl` / `xcomp` 且词形为 `VBG`/`VBN`/`VB` |
| 被动语态 | `auxpass` 依存关系 |
| 现在完成 / 过去完成 | `aux` ∈ {have, has, had} + `VBN` |
| 虚拟语气 | `would/could/might + have + VBN`，或 `were` 用于非真实条件 |
| 倒装 | 疑问语序出现在陈述句，或 `there` 引导之外的移位 |

**轮转**：记录近 8 篇已覆盖的语法点，优先安排**近期未出现**的。
**每篇的目标**：从 8 个语法点里选 3–4 个，每个至少出现 2 处（长难句里自然包含）。

> 依赖：`spacy>=3.8` + `en_core_web_sm`。这是本方案唯一的重依赖（约 12MB），可接受。

## 四、长难句：由真题分布决定

实测四级真题句长分布：**p10=8, p50=18, p90=32 词**。

**目标**：>30 词的句子占 **8–12%**（对应 p90）。
一篇 16 句 → **1–2 句**长难句，其余控制在 10–25 词。

**算法**：spaCy 解析出每句的依存树深度与从句数；长难句定义为
`词数 > 30 且 嵌套从句 ≥ 2 层`。同时标记出来供前端做「长难句解析」。

## 五、AI 味：用可测量的风格指标，不用「AI 检测器」

### ⚠️ 先排除一个错误方向

[Pangram](https://www.pangram.com/blog/why-perplexity-and-burstiness-fail-to-detect-ai) 指出：
困惑度/突发性检测器**不可靠**，会把《独立宣言》判成 AI，**且对非母语写作者误判严重**。

[arXiv 2507.10475](https://arxiv.org/html/2507.10475v1) 也证实：单一风格特征不足以判别，
不同模型族的表现差异极大。

**所以不做「AI 检测器」，而是做「风格指标」** —— 目标不是判别，是**把生成结果朝人类写作的统计特征上拉**。这是可控、可验证的。

### 五个可测量维度

| 维度 | 指标 | 目标 | 实现 |
|---|---|---|---|
| **词汇丰富度** | MTLD / TTR | 高于阈值 | [`lexicalrichness`](https://pypi.org/project/lexicalrichness/) |
| **句长波动** | 句长标准差 | ≥ 6 词（人有波动，AI 均匀） | spaCy 分句 |
| **陈词滥调** | 命中数 | **0** | 30+ 条黑名单 |
| **具体性** | 数字 + 专名 + 引述 | **≥5 处** | spaCy NER + 正则 |
| **重复度** | 重复 4-gram 占比 | 低于阈值 | n-gram 统计 |

**具体性是最关键的一条** —— AI 文章的通病不是用词，是**没有具体信息**。
要求每篇至少 3 处数字、2 个专名、1 处引述。

依赖：`lexicalrichness`（很小）、`textstat`（可读性，参考用）。

## 六、扫词重遇：修掉反了的逻辑 + 新算法

### 现状的荒诞之处

`selection` 第 2 层的条件是 `clean > 0`，而 `clean` = 见过但**没查过**的次数：

> **一个词你查得越多、越记不住，`clean` 越低，越会被排除出重遇。**

你反复查的词恰恰最该重遇，系统却主动回避。

### 新算法

```
score(word) = 3.0 × min(lookup_count, 5)          # 你反复查的，最高优先
            + 2.0 × (12 − encounter_count)        # 离 12 次还差多少
            + 1.0 × min(days_since_last, 30)/10   # 隔得越久越该复现
            − 2.0 × clean_encounters              # 已经很熟的降权
            − 5.0 × (m_level == 'recalled')       # 已掌握的排除
```

**「换语境」要求**：记录每个词出现过的**题材簇**；
重遇时优先选**该词没出现过的题材** —— 这是视频里「不同语境中重遇」的落地。

**每篇的配额**：从上面排序里取 1–2 个高查词词，占用目标生词额度。

## 七、技术架构

### 新增 `app/services/article_quality.py`（核心）

纯代码、不调 AI、可单测。所有维度在此量化：

```python
def analyze(content, ctx) -> dict:
    """ctx: known_set / target_words / target_grammar / recent_articles"""
    return {
        "coverage": 0.951, "coverage_ok": True,
        "out_of_level_words": [...],           # 用于定向修复
        "max_consecutive_new": 1,
        "target_words_missing": [],
        "grammar": {"relcl": 5, "advcl": 3, "auxpass": 2, ...},
        "grammar_missing": [...],
        "sentences": {"n": 16, "avg": 18.2, "long_ratio": 0.12, "std": 7.1},
        "style": {"mtld": 68.2, "cliche_hits": [], "numbers": 7,
                  "proper_nouns": 4, "quotes": 2, "repeat_4gram": 0.03},
    }

def verdict(report, targets) -> tuple[bool, list[str]]:
    """(是否通过, 需要修复的具体问题)"""
```

### 生成流程

```
选题材簇（按真题占比加权 + 近 8 篇轮转）
  → 选语法点（近 8 篇轮转）
  → 选词（扫词重遇 1–2 个 + 新词 N 个）
  → 生成（rich prompt）
  → article_quality.analyze()
  → 通过？保存 : 定向修复 prompt → 重生成（最多 2 轮）
  → 校准 R 与 INCIDENTAL_RATE（累积 20 篇后自动回填）
```

### 新增依赖

| 包 | 用途 | 体积 |
|---|---|---|
| `spacy` + `en_core_web_sm` | 依存句法、NER（语法/长难句/具体性检测） | ~12MB |
| `lexicalrichness` | 词汇丰富度 | 极小 |
| `textstat` | 可读性指标（参考） | 小 |

## 九、仍然需要你决定的（真正的产品选择，不是参数）

1. **目标覆盖率取 95% 还是 98%？**
   - 95%：每 300 词 15 个生词，文章更自然，学习密度低
   - 98%：每 300 词 6 个生词，更舒适，但一篇文章只能埋 1–2 个词
   - Nation 的结论是 **98% 才能「充分理解」**，但 95% 是「能习得」的门槛
   - **我建议 95%**（符合 EDM2022 的习得门槛，且能埋够词）

2. **spaCy 这个 12MB 依赖可以接受吗？**
   它是语法检测、长难句识别、具体性检测三件事的基础，没有替代品。
   如果不想让用户多装，可以做「可选增强」：没装时降级为正则（精度下降但不崩）。

3. **是否同意「不做 AI 检测器，只做风格指标」？**
   基于 Pangram 与 arXiv 的证据，我强烈建议不引入检测器 —— 它会对非母语文本误判，
   而我们的用户正是非母语学习者。
