# 词汇差距：从第一性原理到实施方案

> 版本：草案 v1（2026-09-16）
> 目标：把「提升词汇量」从一句口号，变成一个**可计算、可验证、能驱动阅读**的闭环
> 所有数字都来自本机实测，不是估算

---

## 一、第一性原理推导

```
目标：提升词汇量（大学生四六级，进阶雅思等）
  ↓ 「词汇量」必须有分母才可测 —— 而四六级/雅思恰好是边界明确的考试
手段：以阅读为载体的可理解输入（i+1，95–98% 覆盖率）+ 语境重遇 + FSRS 提取
  ↓ i+1 要求系统知道「你的边界在哪」
度量：词汇差距 = 目标词表 − 已掌握 = 1 − 你在目标语料上的覆盖率
  ↓ 差距必须能驱动「读什么」，否则只是个数字
闭环：按差距选词 → 阅读 → 提取 → 更新掌握度 → 差距缩小 → 再选词
```

**结论：这个产品真正要算的是两个数 ——「你在目标考试语料上的词汇覆盖率」和它的导数（每天涨多少）。现在这两个数都不存在。**

## 二、现状实测：四个断裂点

| # | 断裂 | 实测证据 |
|---|---|---|
| 1 | **数据断裂** | `words` 表 `level` 只有 `CET4`(4,529) 和 `common`(171,247)——没有 CET6 / 考研 / 雅思 / 托福 |
| 2 | **度量断裂** | `vocab_estimate = words_known + words_learning*0.5 + 2000`（`app/api/stats.py:75`）。`+2000` 是写死的常数，当前输出 **2001** |
| 3 | **概念断裂** | `status='known'` **全代码库无一处写入**（测试答对只设 `learning`）→ 系统里不存在「掌握」，`words_known` 恒为 0 |
| 4 | **闭环断裂** | `_select_new_words()` 按 FSRS 优先级 + 词频选词，**完全不知道目标考试** → 阅读补的词和考试要求可以毫无关系 |

也就是说：统计页那个「词汇量」既不是测量的，也不指向任何目标；而阅读引擎不知道该把你往哪个考试带。

## 三、目标词表：真实规模（本机实测）

数据源 **ECDICT**（MIT 协议，770,611 词条，带 `tag` 字段），与现有 175,774 词条匹配率：

| 考试 | 词表规模 | 现有词库能打上标签 | 匹配率 |
|---|---|---|---|
| 中考 | 1,603 | 1,572 | 98.1% |
| 高考 | 3,677 | 3,559 | 96.8% |
| **四级** | **3,849** | 3,828 | **99.5%** |
| **六级** | **5,407** | 5,294 | 97.9% |
| 考研 | 4,801 | 4,734 | 98.6% |
| 雅思 | 5,040 | 4,608 | 91.4% |
| 托福 | 6,974 | 6,612 | 94.8% |
| GRE | 7,504 | 7,162 | 95.4% |

**关键结论：匹配率 91–99%，所以不需要重新导入词典**（释义、音标、词形都已完好入库），
**只要补一列标签**就能打通全部考试。这是一天以内的活，不是一周。

> ⚠️ 注意：ECDICT 的 `cet4` 标签是 3,849 词，而项目现有的 CET4 是 4,529 词（来自另一份词表）。
> 两者口径不同，实施时要选定一个作为「四级」的权威定义并保持一致。

## 四、覆盖率曲线：把「词汇差距」变成可计算的量

### 语料（2026-09-16 全量爬取，替代原先的 205 篇）

`tools/crawl_exam_corpus.py` → `语料库/真题阅读纯文本/exam_corpus.{json,txt}`

| | 仔细阅读 | 长篇阅读 | 选词填空 | 合计 | 词数 |
|---|---|---|---|---|---|
| CET4 | 140 | 70 | 63 | 273 | 134,988 |
| CET6 | 140 | 70 | 64 | 274 | 165,153 |
| **合计** | 280 | 140 | 127 | **547** | **301,313** |

年份覆盖 2015.06 – 2026.06，每篇中位 433 词（真题仔细阅读本就是 ~400–450 词）。
抓取零失败，0 HTML 残留。**原先只有 CET4 的 205 篇，CET6 一篇都没有。**

### 覆盖率曲线

| 认识语料中最高频的 N 个词型 | CET4 覆盖率 | CET6 覆盖率 |
|---|---|---|
| 3,000 | 88.5% | 86.3% |
| 4,000 | 91.6% | 89.5% |
| 5,000 | 93.8% | 91.8% |
| **6,000** | **95.3%** ← i+1 | 93.5% |
| **8,000** | **97.3%** ← i+1 | **96.0%** ← i+1 |
| 10,000 | 98.8% | 97.3% |

**结论（可直接写进统计页）：**

- **四级真题的 i+1 区间是 6,000–10,000 词型**（95–98% 覆盖）
- **六级真题的 i+1 区间是 8,000–12,000 词型**
- 换算成方法里的「300 词里 6–15 个生词」：会 6,000 词时四级材料约 14 个生词（刚好在区间内），
  会 4,000 词时约 25 个（偏难）

交叉验证：Nation (2006) 的经典结论是读懂小说需 98% 覆盖 ≈ 8,000–9,000 **词族**、95% ≈ 4,000–5,000 词族。
本机实测是**词型**口径（词型数多于词族数），量级一致。

> ⚠️ **踩过的坑（留作记录）**：我一开始想用 ECDICT 的 COCA 词频（`frq`）来建模，
> 结果连续算出三个互相矛盾的数字。根因有两条，都已排除：
> ① ECDICT 的词频**挂在词元上，屈折形式 `frq=0`**（`is`/`are`/`has`/`students` 全是 0），
> 必须先用 `exchange` 字段的 `0:lemma` 做词形还原；
> ② 即便还原后，`frq` 字段也只覆盖 770,611 条里的 42,231 条，不足以做覆盖率分母。
> **结论：用「语料内词频」这个自洽模型，它也能与文献对上。**

### 重要副产品：大纲词表覆盖率 ≠ 材料覆盖率

实测：**CET4 大纲词表（3,849 词）只覆盖 CET4 真题语料 15.8% 的 token。**
因为词表装的是**内容词/考点词**，剩下 84% 全是基础词与功能词（the/a/of/is…）。

这意味着：**不能拿「大纲词表掌握百分比」当「能读懂多少」的代理**。必须分两层：

| 层 | 含义 | 作用 |
|---|---|---|
| **词表层** | 离四级大纲还差多少词 | 考试进度指示器 |
| **材料层** | 这篇文章/这份语料你认识多少 token | **决定「该不该读」** |

## 四·五、视频方法的还原与对照（2026-09-16 补充）

视频：**【罗肖尼】如何永远学会一个单词？**（[BV1ns4y1A7fj](https://www.bilibili.com/video/BV1ns4y1A7fj/)，
253 万播放，53 分钟）。理论根基是 **Stephen Krashen 的二语习得理论（可理解输入假说）**。

### 方法的可操作形式（两条规则）

> **① 找词汇覆盖率 95–98% 的可理解文本（300 词里 6–15 个生词），大胆略过生词
> ② 在「变化的语境」中重遇同一个生词 ≥ 12 次**

配套的**选词四标准**：① 日常交谈中有用吗 ② 对理解你的沉浸内容是否必要 ③ 之前见过/觉得熟悉吗
④ 对你个人有趣吗 —— 四条都是「是」才值得花时间。

以及一个关键判断：**学单词是缓慢渐进的过程，不是「会 / 不会」的二元状态。**

### 项目现状对照

| 方法要求 | 项目实现 | 缺口 |
|---|---|---|
| ① 覆盖率 95–98% | `_select_new_words` 每 300 词取 6–15 个生词 | 方向对，但**没有任何地方测量实际覆盖率**，生成完就不知道了 |
| ② 变化语境重遇 ≥12 次 | 只在 `PROJECT_MEMORY.md` 里写了这个数字 | **完全没有实现** |
| ③ 选词四标准 | 只用了一条（②对理解必要） | ①③④ 全缺 |

### 两个必须修正的认知

**修正 1：「重遇」现在根本没被记录。**

`words.encounter_count` 只在**用户查词时** +1（`app/api/reading.py:112`）。
**看到了但没查 = 不算遇见** —— 而方法的核心恰恰是「在语境中反复遇见」，查词只是其中一种反应。
同时 `word_encounters` 表虽然记了 `article_id`，却没有任何地方区分
「同一篇文章里见了 12 次」和「12 篇文章各见一次」—— 而方法的要害正是**语境要变化**。

可落地的口径（数据已够，不用加表）：

```
重遇次数(w) = COUNT(DISTINCT article_id)  where w ∈ target_words(article) ∪ tokens(article)
语境变化度(w) = 不同文章数 / 重遇次数      # =1 表示每次都在新语境；接近 0 表示全在同一篇
达标 = 跨 ≥ N 篇不同文章（N 待定，而非「见 12 次」）
```

关键修复：**文章生成后就要记一次「遇见」**。系统已经从 `articles.target_words`
知道每篇埋了哪些词，不必等用户查词。

**修正 2：「覆盖率」的分母不止是考试词表，更是你正在读的那份材料。**

罗肖尼说的是**材料的覆盖率**，不是「大纲词表覆盖了多少」。所以要分两层，缺一不可：

| 层 | 含义 | 作用 | 现状 |
|---|---|---|---|
| **词表层** | 离四级大纲还差多少词 | 考试进度指示器 | 方案第 2 步要做 |
| **材料层** | 这篇文章你认识多少词 | **决定「该不该读」** | **完全没有** |

材料层才是 i+1 的正主，而且**每篇文章都能单独算**，不用等定级测试。
它也顺带解决了「文章生成后不知道难度合不合适」的问题。

### 选词四标准的项目化落地

| 标准 | 项目已有的可用信号 | 现在用了吗 |
|---|---|---|
| ① 日常交谈有用 | ECDICT 的 `frq` / `bnc` / `collins` 字段（COCA/BNC 词频） | ❌ |
| ② 对理解内容必要 | 目标考试词表 ∩ 材料语料词频 | ✅ |
| ③ 之前见过 / 熟悉 | 重遇次数、`lookup_count`、`word_encounters` | ❌（只当权重，没当**准入条件**） |
| ④ 对你个人有趣 | 查词行为、高亮记录（`highlights`）—— 用户主动查/标的词就是「有趣」 | 部分 |

## 五、方案

### 第 0 步：补考试标签（地基）

- `words` 表新增 `tags` 列（TEXT，空格分隔多标签），在 `COLUMN_MIGRATIONS` 登记，旧库启动自愈
- 新增 `tools/import_exam_tags.py`：流式读 ECDICT csv 的 `word,tag` 两列，按 `text` 匹配 `UPDATE`
- **不重新导入词典**，只补标签；预期命中率见上表

### 第 1 步：定义「掌握」（概念地基，必须先定）

这是现在最缺的东西。三个可选判据：

| 判据 | 定义 | 优点 | 缺点 |
|---|---|---|---|
| A. FSRS 成熟度 | `srs_stability ≥ 21` 天 | 与现有算法天然一致、自动连续 | 只覆盖「学过」的词，没学过的永远不算 |
| B. 测试正确率 | 连续 2 次测试正确 | 直接可测 | 只测过极少数词 |
| C. 自适应定级测试 | 一次性标定全库 | 覆盖全部 17 万词 | 需新功能 |

**建议：C 初始化 + A 持续维护。**

- 首次使用跑一次 **10–15 分钟自适应定级测试**：按语料词频分层（1k/2k/3k/4k/5k/6k 档各抽样），
  答对升档、答错降档，收敛出词汇边界
- 之后 `srs_stability ≥ 21` 天自动标记为已掌握
- **定级测试不是可选项**：没有它，新用户的统计页永远是「2000 + 学过的几个词」，
  反馈循环根本启动不了

产出：`words.mastered`（0=未测 / 1=掌握 / 2=未掌握）

### 第 2 步：把差距算出来（统计页重构）

新增 `app/services/vocab_gap.py`：

```
掌握集合 M = { w : mastered(w) }

覆盖率(exam) = Σ freq_corpus(w) for w ∈ M ∩ corpus(exam)
              ─────────────────────────────────────────
                        Σ freq_corpus(w)

缺口(exam) = |list(exam) − M|          # 词表型考试，可精确计数
```

统计页要显示的指标：

1. **词汇量** = `|M|`（现在恒为 2001）
2. **覆盖率仪表盘**：在四级真题语料上的覆盖率，并直接标出 i+1 区间
   - 「你在四级真题上覆盖 **92.2%** · 距离可理解输入门槛（95%）还差约 1,500 词」
3. **分考试进度条**（缺口 + 百分比）：四级 3,849 / 六级 5,407 / 考研 4,801 / 雅思 5,040 / 托福 6,974
4. **雅思 6 分：不能假装有官方词表。** 雅思没有大纲词表，ECDICT 的 `ielts` 标签是「考试常见词」的近似。
   所以雅思按**覆盖率口径**呈现：「雅思 6 分 ≈ 在雅思阅读材料上达到 ~95% 覆盖」，
   并明确标注口径，而不是给一个假的确切词数。托福同理。
5. **预测**：`预计达成日 = 今天 + 缺口 ÷ 近 30 天日均新掌握词数`
   - 这个数字会逼出真问题（照现在速度要 3 年），**这正是它该起的作用**

统计页示意：

```
词汇量 4,200 词        数据来源：定级测试 + FSRS 成熟度

四级真题覆盖率  ████████████████░░░░  92.2%   离 i+1 门槛(95%) 差 ~1,500 词

四级 3849  ████████████████████░░  87%   还差 500
六级 5407  ████████████████░░░░░░  70%   还差 1,600
考研 4801  █████████████████░░░░░  78%   还差 1,050
雅思 5040  █████████████████░░░░░  （按覆盖率折算，非官方词表）
托福 6974  ████████████░░░░░░░░░░  60%   还差 2,800

按近 30 天日均 +8 词 → 达六级覆盖预计 2027-03-12
```

### 第 3 步：把差距接进阅读（闭环）

改 `_select_new_words()`，在现有 FSRS 优先级之上增加一层目标词表加权：

- 候选池 = **目标考试词表 ∩ 未掌握**
- 排序 = FSRS 到期优先级 × 目标考试权重 × 语料词频
- 每篇文章记录并展示「本篇补的是六级缺口里的这 10 个词」
- 至此，「阅读」和「提升词汇量」才是同一件事，而不是两个功能

### 第 4 步：蒸馏修正（B 方案，已确认）

- 用 `语料库/真题阅读纯文本/all_passages_lazynote.txt`（205 篇真题）蒸馏，替代《傲慢与偏见》
- 画像**降级为微调项**：真题参数是骨架，个人画像只作语气微调
- **摘掉与 i+1 冲突的维度**：删掉「低频词占比」这条提示（它现在在指示模型写 100% 生僻词）
- 修 `app/services/ai.py` 里两套风格源同时注入、互相打架的问题

### 第 5 步：读后理解题（闭环价值高）

- 生成文章时同一次调用产出 3–5 道理解题
- **答对率 → 反推这篇文章是否真在该用户的 i+1 区间** → 喂回选词算法
- 让「难度自适应」从猜测变成测量
- 必须是可选/可跳过，**结果喂算法而不是卡进度**，否则阅读就变成刷题了

## 七、待确认

1. **「视频中的方法」具体是什么？** 本文按项目文档记载的
   「可理解输入 i+1（95–98% 覆盖率）+ 同一生词在不同语境重遇 ≥12 次 + FSRS 提取」来推导。
   如果视频里还有别的关键机制（例如特定的重遇节奏、或"先听后读"之类的顺序要求），
   需要补充进来 —— 那可能会改变第 3 步的选词策略。
2. **四级词表以哪份为准？** ECDICT 的 3,849 还是项目现有的 4,529？
3. **雅思/托福接受「按覆盖率折算」这个口径吗？** 还是你希望给出一个具体的词数目标（那就必须承认那是近似值）。
4. **定级测试做不做？** 它决定了新用户的统计页是「立刻有意义」还是「读三个月才有意义」。
